# Disposable PostgreSQL restore verification

This procedure is a verification drill, not a backup subsystem or retention/RPO/RTO/HA policy. It never targets production/non-disposable data. KELIOS remains undeployed. Database dumps contain credentials/encrypted secrets/personal data; keep them private with restrictive filesystem permissions, outside versioned evidence. Preserve the external RSA/AES keys securely with the database: encrypted OIDC secrets cannot be recovered from database contents alone. Never publish plaintext passwords, tokens, keys, client secrets or raw provider payloads.

`./scripts/smoke-phase4.sh` invokes `smoke-phase4-restore.sh` with the isolated `kelios-phase4` project and disposable fixtures. The restore script refuses another project name. It configures a disabled fixture OIDC provider through the real authorized API (no provider network access), dumps with `pg_dump -Fc`, creates a new uniquely named disposable database and restores with `pg_restore --no-owner`. No original database/table/volume is dropped or overwritten.

Exact sorted row-content digests and counts are compared for all 17 business/history/identity/security/migration tables. The same backend image is temporarily pointed at the restored database through a repository-local Compose override. Required externally mounted RSA/AES files and readiness are checked, then real HTTPS GLOBAL login, authenticated Asset reads and existing restored OIDC secret decrypt/re-encrypt via the production configuration service are exercised. The original disposable runtime database selection is restored afterward. If a drill aborts after switching, rerun the original two-file Compose configuration for the isolated project to return to its original database.

The independent real PostgreSQL Phase4MetadataIT restore case additionally compares every restored row and proves OIDC decryption fails closed while its external encryption key is temporarily unavailable, then succeeds after that same key is restored. Private dumps/configs remain in ignored .cache/phase4-private; evidence contains only digests, status and sanitized assertions. No secret payloads are included.

This establishes the tested local arm64/PostgreSQL 17 deployment envelope only. It does not promise cloud/managed backup availability, another architecture, disaster-recovery timing, key-rotation/retention/privacy policy, or real IServ interoperability.
