# Asset CSV export and legacy import

Use **Assets** in the authenticated KELIOS application. CSV is administrative tooling; ordinary Asset registration and editing remain the standard workflow. These actions do not require a deployment CLI command.

## Export the current Asset result

1. Choose the desired operating Tenant in the top-level context selector, or keep Global to include all authorized Tenants.
2. Apply text search with the search button, confirm any advanced filters, and choose the desired table sort. Unsubmitted text and draft filters are not part of the export.
3. Choose **Export CSV**. Select the desired fields; the nine primary Asset collection fields are selected by default. Check additional fields, including Note or Loan note if needed, and use the arrow buttons to set their CSV order. Keep at least one field selected. Select semicolon, comma, tab or a custom single-character delimiter, then choose **Download CSV**.

The download includes every matching authorized Asset, not just the visible page. Selected CSV headers and cells follow the chosen order. Names and UUIDs of references can be chosen independently. It is UTF-8 with a BOM for common spreadsheet software and uses stable English field-key headers. The backend limits one export to 20,000 Assets and 20 MiB and escapes formula-like cells, including selected notes. If the limit is exceeded, narrow the collection query and try again. ACTIVE Asset readers may export only their authorized scope; TENANT identities remain bound to their signed Tenant.

## Import legacy Assets

Only an ACTIVE GLOBAL ADMIN can open **Import CSV** from Assets. A file may contain rows for different Tenants; each row must identify an existing Tenant. CSV v1 is limited to 5 MiB, 5,000 data rows, 64 columns and 32 KiB per decoded cell. No XLSX or historical checkout/return import is supported.

1. In **File and CSV settings**, select a CSV file. The raw parse preview appears automatically. Choose whether its first record contains headings (checked by default); without headings, the first record is Asset data and the mapper labels its columns **Column 1**, **Column 2**, etc. Choose automatic encoding/delimiter when unambiguous, or explicitly choose UTF-8, Windows-1252 or Latin-1 and semicolon, comma, tab or a custom delimiter. Use **Check file** after changing encoding or delimiter, then verify that German Umlauts look correct in the raw rows. Changing the heading setting reparses the file and clears earlier mapping and Preview choices. Choose **Next**.
2. In **Map columns**, review each source heading or positional column and its example values. Select a KELIOS field or **Ignore** for each column; source headings and order need not match KELIOS. The page shows missing required mappings as you work: Tenant and Location, each by UUID or Name, plus either Product or both Category and Manufacturer. Other fields are optional. Each row must resolve one existing Tenant; an absent or invalid Tenant is a row error. A mapped Product supplies its existing Manufacturer and Category. The historical Tag date is input for a normal KELIOS Tag, not an Asset creation timestamp. Choose **Next** to obtain the initial server Preview for value and reference resolution. No fixed template or saved mapping profile is needed.
3. In **Resolve values and references**, map distinct source enum values and choose ambiguous Name references. Duplicate Tenant names require an explicit existing-Tenant choice. Tenants cannot be created inside Import. A missing other reference is never created automatically: open its normal collection/create workflow and create it under ordinary permissions and validation. Choose **Next**; KELIOS automatically checks a fresh authoritative Preview with the current choices.
4. In **Import preview**, check each row's resolved Tenant, status and warnings. Errors cannot be selected; Ready and Warning rows may be selected. Confirm **Import**. Editing and repeat submission are disabled while it runs. Every selected row is revalidated against current Tenant and references. Successful rows commit independently; a failed row rolls back without stopping later rows. Preview and result identify the original logical CSV record and its starting physical line, including multiline quoted records.
5. A confirmed **Result** shows success/failure/skipped counts and offers a failure CSV containing source columns, record/line references and reasons. This import session is finished; use **To Assets** or **New import** for a fresh session. If the execution response is uncertain, KELIOS shows an outcome-unknown result without invented counts. Check Assets before starting a new import.

Preview does not reserve Tags or references. If a request times out or its result is unknown, inspect Assets before retrying: local identifiers and other legacy input are not globally unique, so repeating a successful row can create a duplicate. Re-import corrected failed rows rather than the whole original file. Import records one truthful initial snapshot and administrative audit action; it does not invent earlier lifecycle or loan history. Some backend-supplied row reasons currently remain in English in the German UI.
