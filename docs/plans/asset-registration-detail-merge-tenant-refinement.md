## Decisions and ownership

HUMAN selected all four supported initial Asset Conditions (`UNKNOWN`, `WORKING`, `DEFECTIVE`, `UNUSABLE`), with `UNKNOWN` preselected. Existing registration always created `REGISTERED` / `UNKNOWN`; neither creation form nor the two HTTP registration variants accepted a Condition. The existing single `REGISTERED` AssetEvent is an initial-state snapshot with absent `before`, so creation must persist the selected Condition and snapshot in the same transaction. Omitted API Condition retains `UNKNOWN` compatibility; explicit null or an unknown value is invalid. Lifecycle selection, transition commands, authorization, Tenant/reference rules, audit/history shape and concurrency behavior are unchanged. DOMAIN owns the Condition rule and OpenAPI owns the optional transport field.

The collection Asset Create dialog and the direct registration route share the exact **Asset erstellen / Create Asset** title, required initial Condition selector and Save semantics. The detail overview groups (1) local identifier, external inventory number, serial number; (2) Product, Manufacturer, Category; (3) Location, Owner, loanability; (4) full-width note; loan facts follow separately. Existing clickable fields and statuses stay interactive. Category and Manufacturer are the only Merge pages; Product Merge remains excluded. Their visible, paged authorized aggregate picker already supplies the necessary cross-Tenant selection, provided it queries the root Catalog route even from a concrete-Tenant page. Remove UUID entry and stale implementation prose; retain preview, final confirmation, server authority and Merge guards. Tenant modal and deep-link detail reuse the shared business identity/metadata hierarchy without inventing Tenant ownership or actions.
