## Contract

Collection toolbars use shared Create, primary text search with magnifier submit, approved immediate selectors, additional filters where needed and one Reset in the main toolbar. In-field X clears one criterion; Reset restores all page-local applied and draft criteria, initial page/size/sort and applicable URL criteria, preserving operating context and identity. Opening an advanced-filter dialog copies applied advanced values into an isolated draft. Confirm applies the draft with other **applied** criteria from page 0; Cancel, Escape, close X and outside dismissal leave the query unchanged. Changed drafts require discard confirmation; unchanged drafts close quietly. No dialog Search/Reset. Business collections show only concise no-records wording. Native trailing actions, table headers, first-cell navigation, focus, keyboard and 1440px/390px layouts follow shared German/English patterns.

Business details show type/title, prominent name (Asset uses its tag), readable Global/Tenant ownership, muted ID, then business fields in collection order where applicable. Finish with compact muted `Created at <when> by <who>` and `Updated at <when> by <who>` lines. Use existing safe projections and unresolved-actor fallback. Authorized view actions are Edit, explicit destructive red **Löschen / Delete**, then Exit where available. The user-facing action never exposes backend deletion terminology. Asset has no Delete UI; its lifecycle/loan/reassignment commands remain separately guarded. No generic More actions dropdown remains on applicable business details.

Category, Manufacturer and Product edit forms offer **Publish globally** as pending edit intent. Selection makes no request. Save applies changed ordinary fields and publication atomically; Cancel/discard applies neither. Current PUT-edit and POST-publish are separate transactions, so extend the strict edit command with optional `publishGlobally` and orchestrate the existing guarded operations in one backend transaction for combined Save. Revalidate authority, state and final reference visibility under existing lock order; if either part fails, commit neither. Unchanged ordinary fields must not trigger the ordinary edit guard or a spurious EDITED AuditLog in publish-only Save. If both operations run, retain their existing audit meaning in one transaction. Preserve POST publish for existing clients, with no immediate detail-page publish control. No Merge or lifecycle policy change.

Audit organizational selector values mean all authorized, known Global attribution, or one Tenant; send neither parameter, `globalOnly=true`, or `tenantId` respectively. `Von`/`Bis` are ordinary native date-time inputs without whole-day/date-only mode or explanatory copy. Existing local-time-to-UTC conversion, invalid-time handling and inclusive backend timestamp range remain. Users enter desired day-boundary times explicitly.

The iServ list is GLOBAL ADMIN read-only, bounded and includes enabled and disabled existing configurations. Proposed `GET /api/v1/oidc-configurations?page=&size=` returns a page of Tenant ID/name, issuer, client ID, enabled and version, deterministically ordered by Tenant name/ID, without secrets, groups, claims or credentials. TENANT ADMIN retains only signed-own singleton read. Existing PUT/DELETE version, audit and authorization semantics remain. Anonymous login organization routing is not this collection.
