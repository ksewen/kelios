## Scope, ownership and dependencies

Make existing Connector detail read-only until GLOBAL ADMIN chooses Edit. The Tenant name is the heading; UUID is secondary, metadata uses the Asset-style footer, and the technical version remains internal. Reload is a labeled icon button beside the heading. The sanitized secret field is a fixed mask or an empty marker, with the separate Set/Change action beside it. The secret is absent from ordinary Edit. A new Connector starts with an explicit Create action and is saved disabled without a secret. The separate Set/Change secret command leaves it disabled. Enable/disable is an immediate versioned save from one button showing the current Ja/Nein state, unavailable while editing; TENANT ADMIN remains read-only. The mapping table has short labels and aligned theme-colored actions. BQ2/BQ3 login mapping and authority are unchanged; BQ4 list wording was committed separately and is not adopted into this gate.

The existing configuration PUT retains legacy secret input and version checks, but permits secretless creation only when disabled. A dedicated versioned secret PUT changes only encrypted secret, version, metadata and redacted audit. V12 permits null ciphertext and prevents enabled rows without a secret. Incomplete Connectors are absent from the public organization directory and cannot start OIDC. OpenAPI, DOMAIN, ARCHITECTURE and the operator guide own the corresponding current contract, policy, technical boundary and setup sequence. BQ4 list wording was committed separately as `cf92702`. No provider interoperability result is implied by isolated tests.
