## Ownership and decisions

This single follow-up gate owns Asset checkout and history presentation. Frontend owns the UI and local-date conversion; `DOMAIN.md` retains the optional `Instant expectedReturnAt` loan rule and immutable `AssetEvent` contract, while `docs/api/openapi.yaml` retains the nullable date-time transport. No backend command, schema, event, AuditLog, authorization, version or operator-data change is approved. O3 and other backlog work are excluded. Do not alter the local manual-review installation.

HUMAN chose 2026-10-19: a selected expected-return date means **23:59:59.999 in the browser's local time zone**, converted to an ISO UTC instant before the existing loan command. In normal Asset checkout, detail and history UI, expected return is a calendar date. Existing arbitrary instants remain stored intact and render as their corresponding local date. Actual loan/event/audit timestamps retain precise time. Checkout UI requires a date; the API remains optional for other clients.

Registration calls `history.append(a,"REGISTERED",actor,null,snapshot(a))`; the writer stores `data.before=null`. There is no supported registration path with prior Asset state. The generic diff currently presents absent `before` keys as *Nicht erfasst* and explicit null `after` values as `—`; these remain distinct historical facts. Normal `REGISTERED` events should render a two-column **Field / Initial state** snapshot of captured, meaningful initial values, including `false` loanability; skip absent and explicitly null optional values. Unexpected or legacy registration events with a non-null `before` retain the generic diff. Other events retain their before/after table. The history table's missing first-to-second vertical divider comes from shared CSS handling `th+th` and `td+td` but not `th+td`.
