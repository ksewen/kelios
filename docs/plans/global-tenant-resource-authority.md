## Scope and authority

This Plan corrects collection visibility, Create ownership, administrative module access, and cross-Tenant reference/Merge integrity. It does not implement unrelated backlog, change credential/OIDC lifecycles, create operator data, or infer write authority from a readable row. For every operation distinguish authenticated principal scope (`GLOBAL`/`TENANT`), role (`ADMIN`/`USER`), operating context (Global/concrete Tenant), persisted ownership, read set, write authority, navigation/direct-route access, reference visibility, and lifecycle commands. Global context is an authorized aggregate workspace, **not** Global resource ownership. Backend authorization is independent of frontend controls.

| Resource | Persisted ownership / authorized read set | Write and lifecycle boundary |
|---|---|---|
| Category, Manufacturer, Product | Global or Tenant-owned. GLOBAL principal: root Global + all authorized Tenant rows; concrete context Global + selected Tenant. TENANT principal: Global + signed-own Tenant. | ADMIN writes to authorized ownership only; GLOBAL ADMIN may target Global or concrete Tenant through existing Catalog routes. Explicit Promote exists; Merge only for Category/Manufacturer. Product has no Merge. |
| Asset | Concrete Tenant only. GLOBAL root aggregates authorized Tenants; concrete/TENANT reads one Tenant. | Every write resolves a concrete Tenant. No Global-owned Asset. |
| Location, Owner | Concrete Tenant only. GLOBAL root must aggregate authorized Tenants; concrete/TENANT reads one Tenant. | Every write resolves a concrete Tenant. No Merge or three-way ownership filter. |
| User | Identity scope is GLOBAL or TENANT. GLOBAL ADMIN reads both; TENANT ADMIN reads own-Tenant Users. | Browser creates GLOBAL Users only; TENANT Users arrive via OIDC. Preserve status/role/self-protection rules and immutable identity/external binding. Profile edit is a decision gate below. |
| Tenant | Tenant is not Global-owned. GLOBAL administrative read sees all; TENANT ADMIN reads own detail. | GLOBAL ADMIN create remains; Tenant principals have no Tenant write. GLOBAL USER's context-label lookup is not module authority. |
| iServ configuration | Tenant-bound singleton, not a Global/Tenant business collection. | GLOBAL ADMIN administers authorized concrete Tenants; TENANT ADMIN signed-own only. Preserve secrets, versions, physical delete and OIDC rules. |
| AuditLog | Captured audit attribution and reader authority, not mutable resource ownership. GLOBAL ADMIN reads all; TENANT ADMIN own-attributed records. | Only owning business/security operations write AuditLog; no manual UI write. |

ACTIVE ordinary GLOBAL/TENANT USERs retain their approved business reads and existing self-service, but have no Benutzer, Mandanten, iServ configuration or Protokoll administration navigation, direct-route access, or administrative API access. PENDING/DISABLED remain restricted. Readable business modules must not be hidden merely because administration is hidden.

### Create ownership and filters

| Family | GLOBAL ADMIN in Global context | GLOBAL ADMIN in concrete context | TENANT ADMIN |
|---|---|---|---|
| Shared Catalog: Category, Manufacturer, Product | Fresh draft defaults to Global; may select authorized concrete Tenant where existing write contract supports it. | Fresh draft still defaults to Global, independently of operating context; may explicitly choose Tenant. | Signed Tenant shown fixed/read-only; backend enforces authority. |
| Concrete business: Asset, Location, Owner | Explicit concrete Tenant selection required; no synthetic Global choice. | Draft defaults to and locks the viewed Tenant for that form session. This is UI workflow, not backend authority. | Signed Tenant shown fixed/read-only. |

Existing Catalog root/Tenant POST routes select ownership; do not invent body `scope`/`tenantId` fields merely for UI state. Audit Product Create/Edit/Publish and references before changing its UI. Concrete-resource writes retain Tenant-path and backend ownership validation. Create selection never changes operating context.

Only Category, Manufacturer and Product expose the compact ownership choice **Alle** (no local predicate), **Nur Globale** (`visibility=GLOBAL`), **Mit Mandant** (`visibility=TENANT`). It narrows the authorized result, never selects a particular Tenant. In Global context the last choice spans authorized Tenant-owned rows; in concrete context it spans only that Tenant's rows. Asset, Location and Owner omit it because every row already has concrete Tenant ownership. Keep other genuinely useful Product filters.

### Reference, Merge and Promote invariants

| Association | Valid | Invalid |
|---|---|---|
| Asset A → Product | Global or Tenant-A Product | Tenant-B Product |
| Tenant-A Product → Category/Manufacturer | Global or Tenant-A label | Tenant-B label |
| Global Product → Category/Manufacturer | Global label | Tenant-private label |
| Asset A → Location/Owner | Tenant-A reference | Tenant-B reference, even when actor is GLOBAL ADMIN |

Validate at the authoritative transactional write boundary, including retained/deleted dependents where existing Domain guards require them. An aggregate read does not authorize a cross-Tenant association.

Category/Manufacturer Merge must leave every surviving Product/Asset reference readable to its dependent Tenant **at commit**. Same-Tenant and Tenant-source → Global-survivor directions may succeed when other guards pass. A Tenant-private survivor cannot receive foreign-Tenant or Global dependents. Reject unsafe Merge with a stable machine-readable problem code and localized instruction to **Promote the intended survivor to Global first**. Rejection changes no reference, source deletion, AssetEvent or AuditLog. Never auto-Promote. Promotion retains the same ID, widens visibility and remains GLOBAL ADMIN-only; no demotion or clone is introduced. Preview is advisory; execution revalidates under concurrency.
