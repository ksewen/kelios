## Phase B — Merge selection

The original Merge source/target selectors were replaced with one inline, nonmodal combobox per participant. A floating result list had clipped inside the Dialog, so the bounded list joined its layout. Text query, selected persistent UUID and captured readable label stay separate. A changed query clears the old UUID and resets page; paging or a same-context refresh preserves a selected UUID even when it is absent from the current page. Duplicate names show Tenant/Global context and UUID suffix; names grant no authority. At that date search used authorized `page,size=25,q` with explicit Previous/Next; later F2 changed lookup batching. Retained pending options are subdued and disabled; stale results are rejected. Equal or missing UUIDs cannot preview/execute; participant changes invalidate preview and late preview responses. The existing backend still receives only source/target IDs and revalidates authoritatively. An explicit-ID section remains a way to supply a known UUID, not a new scope. The popup uses listbox/option semantics, arrow/Enter/Tab navigation and a scoped Escape capture so Escape closes the popup before the parent Dialog.

`npm test` **51 passed** in four files, `npm run build` passed, focused Chromium **30 passed** (14 Merge +16 unchanged stability), and a further **2 retained-option identity checks passed**; `git diff --check` passed. The non-TLS Playwright configuration excluded seven real-backend `inventory.spec.ts` cases despite that file appearing in the command; they were **not** counted as passes or skips. Wrong initial npm cwd, sandboxed Chromium launch, Shift+Tab test invocation, popup Escape dismissing the Dialog, disabled paging-button focus loss and clipped floating options were found and corrected before the green run. A read-only normal-HTTPS production inspection showed two comboboxes and zero native selects in Category/Manufacturer Merge for DE/EN, empty-search behavior, retained focus, no page errors/writes. Fixture workflows with duplicate names did **not** constitute a real Merge execution. No persistent data was created.

## B.1 — form/create and picker consistency

Five Catalog/Place creates, Asset registration, Tenant and GLOBAL User create, action forms and relevant credential fields were audited for controlled-state ownership. Independent create drafts now clear on success; errors retain input. A blank Merge `role=status` paragraph had reserved **20px** even when ready; it now exists only while pending, with **zero ready status rows and a 5px option gap** in inspected production. Merge advisory preview and execution stay inside one mounted Dialog; only consequential execution asks for confirmation, and stale preview generations cannot be submitted. Product and equivalent Asset entity references adopted the searchable UUID combobox; enum/catalog-mode choices remained native selects. Optional references can clear; a required reference must resolve to an ID. At this checkpoint, Cancel/X retained drafts; **B.2 superseded that rule**.

Actual create/success-reopen and destructive workflows used intercepted responses, not operator records. Pre-B.1 Phase A evidence was hash-preserved. ## B.2 — ephemeral writes, discard and compact toolbars

The key accepted rule became: **read results may remain mounted; unsent write drafts live only in the active form session**. A real Product Cancel had left zero dialogs but one hidden dirty marker; later navigation therefore prompted discard. `Command` now marks the active form, applies explicit state resets and treats form Cancel, X, Escape, outside click, context/navigation/logout through the existing confirmation and router guards. Rejecting discard retains the exact mounted input/value/focus; confirming clears it; reopen initializes blank create or current authoritative edit. Failure retains input. A submission in flight cannot be dismissed and silently cleared. Merge participants/query/preview, registration, User/Tenant create, Asset action fields, credential/password fields and OIDC write-only secret each follow their applicable session ownership. Consequential action confirmations remain separate; no persistent draft system or broad state framework was added. Outside-click testing exposed focus returning to body after rejection; the shared confirmation path restored focus to the mounted form.

The visible actions became concise Create/Erstellen, Merge, Preview/Vorschau and Confirm/Bestätigen where applicable. Resource-specific commands and security labels remain explicit. Category/Manufacturer use Search→Create→Merge; Product/Location/Owner Search→Create; Asset search/sort/filter/concrete-Tenant Create remain resource-specific. Responsive flex wrapping preserves semantic order, authorized action visibility and no page overflow; no speculative controls were added.

Verification: **51 units**, production build, **67 intercepted Chromium tests**, then **5 repeated outside-click cases** separately; `git diff --check` passed. Earlier **59/60** and **65/66** runs were superseded by the complete green run. A hidden link in an open modal required a specific router-dispatch locator; an initial shell command used the wrong cwd. Real HTTPS DE/EN inspection covered 32 page/viewport combinations at 390/768/1024/1440 with no horizontal page overflow; Product rejected discard retained input and confirmed discard reopened blank; **zero business writes/page errors**. No concrete Tenant existed for manual Location/Owner inspection; those controls were tested with intercepted fixtures. `inventory.spec.ts` remained excluded. A direct document GET `/assets` returned **301** to unexposed `https://localhost:8443/assets/`; in-app navigation worked. This was **fixed in B.3**, not B.2. No real Merge, destructive operation or successful create was executed against operator data.

## B.3 — applied filters, quiet reads and direct routes

Ordinary Name filters became explicit pending input plus Apply; typing does not query, Enter/Filter applies once, and applied criteria survive page/sort transitions. Reference pickers and public organization routing kept immediate bounded search, separate from list Apply. Same-context refresh keeps mounted data/input/table, without a visible updating paragraph or reserved row; pending stale options stay disabled. Initial loading, empty, error and mutation progress remain meaningful. The browser's `/assets` direct-route failure came from nginx's static `/assets/` handling and TLS port redirect. The exact route repair served the SPA document for application routes while preserving real static assets, missing-file 404s and API proxy behavior.

Verification: **51 units**, production build, **76 intercepted Chromium cases**, **17 HTTPS +17 HTTP real-nginx routing checks**, `git diff --check` passed. An early **72 pass/1 fail** run happened during HMR source changes; a **75/1** locale failure used separate warm-HMR i18n module instances; clean-server rerun passed all76 without weakened product assertions. A sandboxed launch and inspection-script Escape retries were harness issues. Read-only production checks covered **12 routes and refreshes**, each 200, and unauthenticated `/assets` leading to normal login. In DE/EN at four widths, Product Name typing sent **zero** list requests; Apply sent **one**. Input/table nodes and dirty-form behavior remained stable, with no page overflow, uncaught page errors or business writes. Expected initial unauthenticated 401 and deliberate nonexistent-detail/history 404 were distinguished from page errors. The first pointer X with an open Merge popup sometimes failed to close: its cause was still unknown at B.3 and was resolved in B.4. The environment had no selectable Tenant or populated Asset for manual Place/detail evidence; fixtures did not prove those live workflows. Real-backend `inventory.spec.ts` remained excluded.

## B.4 — confirmation, sorting and first-click repair

Pointer Cancel restores focus without a spurious outline; keyboard Escape/Enter preserves visible focus. The originally reported pointer ring was **not reproduced** in initial production inspection; the correction makes modality handling deterministic without suppressing all outlines. Advisory Merge Preview remains localized, quiet, disabled/`aria-busy` while pending and guarded against duplicate dispatch; write submission retains progress feedback. Cancelling a pre-submit confirmation for Merge, publication, Asset deregistration or User disable returns a local no-submission outcome: **no request, success state, reset or warning**. Dirty exit and uncertain/dispatched mutation outcomes retain separate policies. Category/Manufacturer merge candidate popup closing during pointer-down caused the centered Dialog to shrink: Close moved from top **121.5 to 176.5px**, mouseup hit a DIV and click hit BODY. Preventing that focus transfer on the existing semantic Dialog.Close keeps the target until click; no extra close handler or modal was added. Keyboard Escape still dismisses the nested popup first.

Asset Tag, Created at, Lifecycle and Condition headers gained supported server sort/direction and `aria-sort`; a Created at column gave the default sort a real header. Rows preserve server order (including an intentionally Z-before-A fixture). Sort/page use the **applied** filter snapshot; pending text does not leak before Apply; sort resets page. Unsupported columns are not made sortable. These were then superseded/extended by accepted backend query and F2/F3 integration; the Phase B.4 audit's size25, User array, deleted filters, UUID tie-breaker and backend-gap matrix are **historical observations**, never current Domain rules. The Product Name at390px was still hard to read at B.4 and was separately corrected in O2. Broad column-associated filter presentation remains separately open.

Verification: **51 units**, production build, **112 intercepted Chromium** passed, plus **26 strengthened filter/Preview cases rerun** (not additional distinct tests), **17 HTTPS +17 HTTP routing checks**, `git diff --check` passed. Initial Sidebar regression failures came from obsolete Asset selectors; only selectors were updated, keeping authorization/mobile assertions. Premature blank screenshots were rejected and recaptured after ready state; they were not used as visual proof. Real production inspection covered **56 ready DE/EN page/viewport combinations** (Manufacturers, Products, Assets, Users, Tenants, Audit, IServ prompt ×390/768/1024/1440), with no page-level overflow; narrow Asset table scroll was intentional. A read-only Merge preview used existing operator Categories; cancelling final execution generated **zero mutation requests**. Production sort sent `page=0,size=25,sort=tag,direction=asc` at that historical stage while pending identifier text stayed unsent. Runtime recorded `writes=[]`, `errors=[]`. `inventory.spec.ts` and `authentication.spec.ts` were excluded in the non-TLS fixture configuration, **not** passed or skipped. No Tenant/provider/Asset data was fabricated, no real business write occurred, and the 390px Product limitation was expressly outside B.4 acceptance.
