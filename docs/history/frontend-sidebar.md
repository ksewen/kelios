## Identity audit and retained rendering rules

The supporting audit inspected React keys, reads, session/context boundaries, Dashboard, history, Merge, OIDC drafts, sidebar, dialogs, lazy routes and CSS. Its cause was state and component identity tied to translations, query revisions or new response objects. Read results stay mounted during a valid same-context query; the latest response wins and a changed authorization/session/resource invalidates old state. Same-session token renewal does not need to recreate reads. Stable IDs identify rows, cells, sidebar groups, Dashboard metrics, history fields and Merge participants. Shell's semantic view boundary changes on true session/User/scope/Tenant/role/status/workspace/path changes, not translation or query edits. OIDC draft fields initialize once per mounted context; subsequent reads do not overwrite active input. Dialog opening and closing intentionally mounts/unmounts their content; the accepted write-session policy was later refined in Phase B.2. No universal fetch/cache/memoization framework or backend authority change followed from this audit.

Audit verification: `npm test` **51 passed** in four files; `npm run build` passed; `npm run test:smoke -- tests/search-stability.spec.ts` **16 intercepted Chromium cases passed**; `git diff --check` passed. The temporary Vite server was stopped. Earlier sandbox/clock/import/response-release harness failures were corrected; the expanded invariant tests passed. The audit was representative, not every dialog/browser/network permutation. Merge refresh identity and OIDC draft initialization lacked dedicated end-to-end cases in that original run; subsequent accepted tests cover relevant shared behavior, without retroactively changing that result.
