Phase 3's Audit attribution analysis established that a retained administrative event must carry authoritative actor and target Tenant in the writer transaction; the later backend program kept that rule. Phase 4's invariant coverage mapped reference guards, rollback, OAuth security, localization and restore to executable tests. Durable runtime branding and disposable restore procedures are in [operations](../operations/runtime-branding.md) and [development](../development/isolated-restore.md). Original Plan/report/raw-output bytes remain available in Git history at the accepted commit; transient hashes, image IDs, log lines and intermediate screenshots are not active contracts.

The retained Phase 1 initial-failure log recorded two **failing assertions** in `DomainFoundationIT`: PostgreSQL `55P03` lock timeout surfaced as `UncategorizedSQLException` instead of the originally expected `PessimisticLockingFailureException`, and concurrent Asset update surfaced as `OptimisticLockException` instead of `ObjectOptimisticLockingFailureException`. It was a 37-case run with two failures, not accepted proof. The final tests/exception classification were reconciled and passed. Phase 3's generated action-count JSON enumerated successful administrative actions in an isolated fixture, including Catalog/place create/edit/delete/Merge/publication, Tenant/User/bootstrap/credential and OIDC changes; its numerical row frequencies depended on fixture repetition and are not production frequencies. Phase 4's source/restored digest files each covered **17 tables and were byte-identical**; the separate authentication result recorded restored HTTPS GLOBAL login, scoped Asset/localIdentifier reads, external-key OIDC secret decrypt/re-encrypt and exact all-table digest comparison. Missing-key fail-closed was separately exercised by PostgreSQL `Phase4MetadataIT`. These conclusions survive without retaining transient raw log/digest bytes.
