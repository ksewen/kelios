# ADR 0003: Phase 2 stateless authentication and explicit authorization

**Historical accepted implementation record.** Preserve the decisions and evidence below as implementation-time history. Current normative Domain/identity/query requirements are in [DOMAIN.md](../../DOMAIN.md) and [ARCHITECTURE.md](../../ARCHITECTURE.md); separately approved future work follows [the consolidated implementation gates](../plans/COLLECTION_QUERY_IMPLEMENTATION_PLAN.md). Earlier login identifiers/password minima, paging defaults, deleted selectors, sort ties and phase-specific exclusions are not competing target requirements.


Status: Accepted through the user's Phase 2 implementation approval and D1–D9 decisions, 2026-10-10. Scope: Phase 2 only. Latest clarification permits complete documented IServ implementation without real-provider access this cycle; interoperability remains pending manual evidence.

## Authority and preserved baseline

[Domain](../../DOMAIN.md), [Architecture](../../ARCHITECTURE.md) and the approved [Phase 2 plan](../plans/PHASE_2_PLAN.md) are authoritative. Preserve [ADR 0001](0001-phase-0-foundation.md) / [ADR 0002](0002-phase-1-domain-persistence.md), Java 25, Boot 4.1.1, Maven 3.9.16 Wrapper, Node 24, separate non-root multi-stage images, runtime branding, V1–V3, minimal User and all accepted Phase 1 constraints/history/locking. This ADR resolves the earlier future browser-transport proposal; it does not rewrite historical ADRs or Phase 0/1 evidence.

## Decisions

- D1: memory-only Access Bearer + Secure/HttpOnly/host-only Refresh cookie, same-origin HTTPS only, CORS off. Refresh/CSRF cookie path `/api/v1/auth/`, SameSite Strict; encrypted OIDC flow cookie uses Lax for top-level callback. Signed stateless double-submit proof bound to valid Refresh `jti`, exact configured Origin on unsafe auth requests. No server session/BFF/revocation store. Logout clears browser state only.
- D2: supported Spring Security Argon2id, Bouncy Castle implementation; Unicode code-point password policy and canonical ASCII login from Domain. Selected cost m=19,456 KiB/t=2/p=1, salt=16/output=32, benchmarked with 512 MiB JVM and two processors. Dedicated GLOBAL-only credentials; initial/reset password is actual credential, no forced-change state. Administrative reset and current-password-verified own change share policy.
- Revised D3: explicit deployment-side non-web bootstrap/recovery at zero usable GLOBAL administrators. Singleton seeded guard row is only a mutex, not completion state. Guard/check/User/credential/audit are atomic; usability-increasing GLOBAL administrator operations share this narrow guard. Reject normal destructive self account changes; no permanent minimum-admin rule. Input password file only, no default/generated production credentials.
- D4: Nimbus JOSE/Spring-managed security dependencies, RS256, mounted minimum-3072-bit RSA PKCS8/X509 keys, trusted local `kid` lookup. Validate issuer, distinct audiences, Access/Refresh JOSE type and `token_use`, iat/nbf/exp and 30-second skew. Access 15 minutes; Refresh original absolute 30 days unchanged. Reload and briefly share-lock current User during refresh. No stored tokens, blacklist, authVersion, tokensValidAfter, per-device sessions or password-change revocation.
- D5: additive Flyway V4 adds `local_global_credential`, `tenant_oidc_config`, `tenant_oidc_allowed_group`, `external_identity`, `global_admin_recovery_guard`. Composite FKs bind GLOBAL credentials and TENANT identities to explicit User scope/Tenant; issuer/subject exact unique; login canonical unique; UUID allowlist and versioned provider settings. No new triggers or authentication columns in core User.
- OIDC secrets: externally mounted versioned AES-256-GCM key; fresh nonce/authentication tag and purpose/Tenant/issuer/client AAD. Bounded authenticated encrypted five-minute flow cookie holds state/nonce/PKCE S256 context; no HTTP session or authorization-request table. Discard provider tokens after validated handling. API secret responses are sanitized.
- Dynamic database provider resolution uses Discovery, bounded verified-configuration metadata/JWKS caching (128 entries/60 seconds), Spring OIDC token validation and bounded Apache HttpClient TLS requests. A narrow application OIDC service owns cookie/code/JIT choreography instead of default session-backed authorized-client persistence; all standard protocol validations remain enforced. Verify issuer, endpoints, trusted-host/DNS policy at actual connection, TLS chain/hostname, response limits/timeouts, no redirect/cookie/retry persistence, discovered JWKS and trusted signing algorithms, audience/nonce, code/verifier and callback/provider/config-version binding. Private/secondary hosts and optional private CA trust store are deployment-controlled, never test bypasses or hard-coded Tenant/provider values.
- D6: official IServ [scopes/claims](https://doku.iserv.de/manage/system/sso/#scopes-und-claims) and [UserInfo example](https://doku.iserv.de/development/oauth/) establish `iserv:groups` scope/claim and list objects with group UUID `id`, account `act`, display `name`; UserInfo `sub` must match verified ID-token subject. Match UUIDs only and deny missing/malformed/unavailable/empty-intersection conditions. No WebUntis role semantics or guessed claim/API.
- D7/D8: administrator-created GLOBAL users are USER/ACTIVE, separate ADMIN grant. JIT creates exact TENANT/USER/PENDING. IServ login eligibility does not continuously synchronize accounts or run at KELIOS refresh; manual DISABLED prevents future refresh, old Access naturally expires.
- Explicit authorization predicates live in identity/application security, with immutable validated principals and secured Phase 1 application wrappers. Load targets/current scope/visibility/Tenant server-side in operation transactions; preserve Catalog publication/mutation races and Asset versions. Entities and generic engine remain independent. Identity/admin HTTP endpoints only, no inventory API/UI.
- D9: atomic sanitized administrative AuditLog; bounded status-only operational failures, no permanent per-login audit/security domain. No secrets/password hashes/provider payload in logs. Auth callback access logging excluded. Process-local bounded throttling complements deployment ingress limits without Redis or forwarded-header trust.

## Transactions and verification boundaries

Keep READ COMMITTED and explicit operation-local locks. Recovery/usability guard before relevant User locks; credential login rechecks User/credential after expensive verification; refresh User SHARE versus administrative UPDATE; external-identity unique reservation plus deferred User FK; final OIDC config SHARE/version/fresh groups versus versioned config UPDATE; fresh locked Catalog visibility authorization. No generic locking framework or universal isolation/retry protocol.

Real PostgreSQL/Testcontainers verify structural/concurrency semantics and V1–V3 upgrade preservation. Test-only HTTPS OIDC fixture exercises real Discovery/token/JWKS/UserInfo requests and PKCE against the documented contract, using production TLS trust configuration. No production mock-provider mode. Separate Playwright tests exercise real TLS local authentication/cookies/CSRF/refresh/logout and minimal pending/completion browser states; browser contract fixtures are explicitly labeled and do not prove provider interoperability.

Implementation completion, deterministic documented-contract verification, and actual IServ interoperability are distinct. The first two may pass this cycle; actual IServ remains pending because no environment is available. [Manual procedure](../verification/PHASE_2_ISERV_MANUAL.md) requires configuration and sanitized evidence only, no code changes. [Phase 2 evidence](../verification/PHASE_2.md) records actual commands/counts/results and limitations.

Phase 3, credentials for Tenant users, automatic ADMIN mapping, Product/Owner/Location Merge, inventory workflows/UI, privacy/deletion/reactivation policy, cross-origin browser support and authentication/session persistence remain excluded. No commits or pushes are part of this decision.
