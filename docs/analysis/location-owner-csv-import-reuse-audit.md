## Accepted-main recheck and changes since the original audit

The merged `b741076d` tree was compared with the accepted Asset feature tip `86fc40990852b8d939f0c34e611bcbdeefb5383e`. Blob IDs match for `PlaceModel`, `PlaceService`, `PlaceOperations`, `PlaceDtos`, `PlaceController`, V2/V7 migrations, `AssetCsvParser`, `AssetCsvImport.tsx`, `pages.tsx`, `capabilities.ts`, DOMAIN, OpenAPI, and the Asset CSV Plan. Current ARCHITECTURE §5 keeps Asset CSV isolated from normal Place commands; §13 retains the Location/Owner Create form and concrete-Tenant rules. DOMAIN §5/§12 and OpenAPI `PlaceCommand` retain name/optional-note semantics. Thus all original Place creation and duplicate-name findings still hold; no new backend business functionality is required.

The material change is acceptance and integration of the Asset CSV UI. The accepted `frontend/src/features/inventory/AssetCsvImport.tsx` now has a guided flow; its file settings at lines 41–68 and 109–117 hold encoding (`AUTO`, UTF-8, Windows-1252, ISO-8859-1), delimiter (`AUTO`, semicolon, comma, tab, custom), header checkbox, invalidation on settings changes, parse errors, and source record/line preview. These controls remain inline in that Asset-specific component; no generic settings component or hook is exported. `frontend/tests/asset-csv-import.spec.ts` covers its flow and headerless behavior. Copying the wizard's field mapping/reference resolution would enlarge this Place feature without need.

The accepted `AssetCsvParser` remains a backend `@Component` with package-private parsed data, `MultipartFile` input and Apache Commons CSV dependency. `AssetCsvPreviewService.parsePreview` and its `/api/v1/asset-csv/parse-preview` route require GLOBAL ADMIN. Its AUTO delimiter path still discards parses with fewer than two columns; a one-column CSV needs an explicit delimiter if this parser is used. This limitation is expected. `backend/src/test/java/com/github/ksewen/kelios/platform/security/AssetCsvParserTest.java` covers quoted/multiline, BOM, legacy encoding overrides, headerless rows and bounds, but not Place-specific authority or one-column AUTO. No accepted frontend CSV parser dependency exists.

## Architectural recommendations, not approved implementation

**CSV configuration UI reuse:** Follow the accepted Asset importer's encoding, delimiter, invalidation, parse-error and source-preview interaction where applicable. The Place control requires an explicit header yes/no choice and a concrete delimiter rather than AUTO. Implement it locally; no shared component extraction is justified solely by this one-column import. This decision is independent of parser reuse.

**CSV parser reuse decision:** The approved source has one name column, so a bounded Place-local browser parser is the smaller implementation. Use browser decoding for the approved encodings and handle quoted fields, doubled quotes, record/line numbers and bounds; reject malformed input or extra columns before execution. Direct use of the Asset parse-preview route is unsuitable for TENANT ADMIN. A shared backend endpoint or extraction would add transport/security work and Asset coupling without serving this narrow contract. Do not change Asset AUTO delimiter detection solely for this feature. If the source contract later expands, reassess backend reuse under a revised and separately authorized plan.

**Place execution:** Use existing JSON Create APIs per row, with one fixed target Tenant and `{name, note: null}`. This supports independent transactions and partial success without a new bulk API. Preserve row identity and backend error codes. Duplicate names are permitted; no duplicate precheck or overwrite follows from the Asset warning logic.

## Approved source decision and remaining gate

- On 2026-10-31 the HUMAN selected an iServ-independent CSV contract: exactly one name column; explicit header yes/no setting; headed files accept only `name` case-insensitively; no aliases; additional columns fail rather than entering field mapping. A representative iServ export is not a prerequisite.
- Follow Asset encoding choices and explicit delimiter controls. AUTO delimiter detection is unnecessary for one column; the Asset parser's limitation remains expected behavior, not a defect. Quoted fields and record boundaries need correct CSV parsing so source names are not silently altered.
- The parser and UI design are now specified in the owning Plan. Only exact implementation-gate authorization remains; no code or test changes are approved by this audit update.
